# Flint: the feed and the owner API

Flint's gateway serves a read-only JSON feed for the arena page and anyone else, and an owner API that a CIP-30 wallet signs into. Both sit on the gateway's port (`--port`, 4482 by default): the page at `/`, the feed under `/feed/`, the owner API under `/owner/`. The live demo is `https://flint.odatano.dev/`, its feed `…/feed/<route>` and its owner API `…/owner/<route>`. `npm run mock-feed` serves the same shapes with made-up numbers on port 4481.

Feed routes: `meta`, `agents`, `quotes`, `fills`, `decisions`, `refusals`, `proofs`, `capital`, `revenue`. The page polls all but `capital` every 5 s. `fills`, `decisions`, `refusals` take `?since=<ISO timestamp>` and come newest first. CORS is open.

Agents' tools: `POST /mcp/<agentId>` on the tools port (`--tools-port`, 4483; the live demo at `https://flint.odatano.dev/mcp/<agentId>`) is a stateless streamable-HTTP MCP server with the agent's tools: get_mandate, get_market, get_account, preview_action, post_quote, take_quote, place_order, hedge, cancel_all, close_position. A paid tool answers 402 with an x402 price first; an agent with a tools key answers only with `Authorization: Bearer <key>`. `meta.tools` carries the public address and the prices.

## The owner API

Next to the feed, under `/owner/` (so `https://flint.odatano.dev/owner/…`), for the page's Terminal and Console. A session comes from a CIP-30 wallet: `POST challenge {address | addressHex}` answers `{nonce, message}`, the wallet signs the message with `signData`, `POST session {nonce, signature: {signature, key}}` answers `{token, address, agents}`; `agents` are the ones whose mandate names that address as `owner`. With `Authorization: Bearer <token>`: `GET session`, `DELETE session`, `GET agents` (full mandates and state: `stopped`, `unwinding`, `frozen`, `toolsKey`, `strikeKey`), `POST agents/:id/pause`, `/resume`, `/stop` (stop means flat: a freeze by hand, offers and tool orders pulled, what is still unhedged sent to Strike at once as a market order, a resting limit replaced by it; when Strike cannot fill it a limit rests again and the card counts it under `resting`; nothing new until a mandate is signed), `/close` (reduce-only market order per market), and `PUT agents/:id/mandate {mandate, signature}` where the signature is `signData` over the mandate's hash (`canonical` JSON, SHA-256, as the page computes it). A signed mandate is in force from the next round, in the hedgers too (band, deadline), saved under `data/mandates/`, loaded on the next start, and anchored on the vault again. Sessions last 12 hours and survive a gateway restart; a stop, a pause and an unwind survive one too. Errors come as `{error}` with 400, 401, 402 (an x402 price to pay first), 404, 409, 500, 501 (the feature is off on this gateway), 502 or 503 (Strike or the chain did not answer); a close that Strike refused answers 200 `{ok: true, error}`. `meta.owner` says the API is on; `meta.tools` carries the public tools address and the x402 prices. `npm run owner -- …` does the same from a shell with a headless owner key.

A new agent is an order the owner pays from their wallet. `GET prices` (no session) says what it costs: `{feeAda, feeClaudeAda, keyAda, minDepositAda, payTo, x402}`; the same sits on `meta.orders`. `POST agents {name, mind, mandate, signature, depositAda, toolsKey, pay}`: `name` is `^[a-z0-9-]{3,14}$` and not taken, `mind` is `rules` or `claude`, `mandate.agentId` is the name, `mandate.owner` the session's address, the signature is `signData` over the mandate hash as for `PUT mandate`, `depositAda` at least `minDepositAda`, `toolsKey` true by default, `pay` is `wallet` (default) or `x402` (the set-up fee charged on this call, 402 first as at the tools endpoint). It answers 201 `{agentId, index, hash, job}` and the job starts. Then the owner's one payment, built by the gateway and signed by the owner's wallet: `POST agents/:id/pay/build {utxos?}` answers `{unsignedTxCbor, outputs, total}`, a transfer with the set-up fee to `payTo` (left out when x402 paid it) and the deposit plus 5 tADA to the agent's own Cardano wallet (`utxos` are the wallet's CIP-30 hex UTxOs, the page sends `api.getUtxos()`; without them the gateway reads the chain); `POST agents/:id/pay {unsignedTxCbor, witnessSetHex}` (or `{signedTxCbor}`) submits it. The agent's wallet then deposits at Strike itself: Strike builds deposits only for the wallet it registered at builder connect. `GET agents/:id/onboarding` reads the job, `POST agents/:id/onboarding/retry` runs it again from the step that failed, `POST agents/:id/onboarding/cancel` takes an order back while its `pay` step is not done (the job ends `cancelled`, the card leaves the feed, the name is free again, the wallet index stays used; 409 once paid). A name is taken by a built-in, an agent in the loop or the registry, an order under way, or a Strike account made for it. The job:

The payment is built over the wallet's own coins (`POST agents/:id/pay/build {utxos}` with the CIP-30 UTxOs, hex): coins that carry a reference script or a datum stay out (the chain is asked, since a wallet's hex may leave the script out), tokens on a spent coin come back in the change, the fee follows the transaction's size. `POST wallet/spendable {utxos}` says beforehand what a payment can spend: `{totalLovelace, spendableLovelace, onScriptsLovelace, coins, withTokens, withScripts}`. A wallet that cannot carry the payment has the other way: the same money plus 1 tADA (`manualLovelace` on the job) sent to the agent's own address (`cardano` on the job) from any wallet; the `pay` step looks at that balance every half minute, takes it, forwards the fee to the project from there and stops waiting for a signature.

`status` is `pending`, `running`, `failed`, `cancelled` or `done`; a step's `status` the same but `cancelled`. The steps: `wallet` (its Cardano and Midnight wallets), `pay` (the owner's transaction, waited for up to 45 minutes, then seen on chain), `account` (builder connect), `deposit` (the agent's wallet deposits at Strike: quote, build-tx, its signature, submit, confirm), `mint` (quote-sized tBTC and tUSD coins to its closed wallet), `credit` (Strike credits the deposit), `open` (its NIGHTGATE server, wallet synced), `register` (into the loop and `data/agents.json`, mandate anchored, its tools key issued when ordered: `toolsKey` is in the first view that carries it and null after, the gateway keeps only its hash), `quote` (its first offer). From the first step on the agent has a card on `agents` with `status: "starting"` and `onboarding: { status, step, stepStatus, detail, error }`; once the job is done `onboarding` is null and the card is the loop's. Eight to ten minutes from the payment on. `npm run owner -- create <name> [rules|claude] [x402] [deposit=850] [path=value …]` then `npm run owner -- pay <name>` does it headless from the owner key's own tADA; a list value is JSON, so `strike.markets=["SOL-USD"] midnight.pairs=["tSOL/tUSD"]` orders a single-market maker.

Payouts: `POST agents/:id/withdraw {usd | "all"}` takes that much off the agent's Strike balance and brings it to the owner's wallet: Strike pays to the wallet it registered at builder connect (the agent's own), the gateway forwards what landed (never more than the quote at its rate, so a deposit arriving meanwhile stays), and the agent's wallet keeps its own tADA, at least 3, for Strike's next request. It answers 201 `{job}` with the steps `quote`, `sign`, `confirm`, `settle` (Strike's validators, up to two hours), `forward`; the view carries `usd`, `askedUsd`, `cappedFromUsd`, `feeUsd`, `limit`, `requestId`, `strikeStatus`, and at the end `paidOut` (lovelace) and `txHash`. Strike allows a set amount of ADA per asset per hour and per day (100 and 500 on testnet): the quote step caps the amount at what is left, converted at Strike's ADA mark, `cappedFromUsd` says what was asked and the step's `detail` when the rest can follow; with nothing left the job fails with the time. `GET agents/:id/withdrawals` answers `{withdrawals, room}`, newest first; `room` is what Strike lets go right now: `{availableUsd, limitUsd, nowUsd, adaUsd, hour: {limitAda, usedAda, remainingAda, resetsAt}, day: {…}, largeAboveAda, largeDelaySec}` (null when Strike did not answer). `POST agents/:id/withdrawals/retry` runs the newest payout again from the step that failed. Open positions keep margin in use: stop the agent, then `POST agents/:id/unwind` (below) for everything. `npm run owner -- withdraw <name> <usd|all>`, `withdrawals <name>`, `retry-withdraw <name>`.

Deposits into a running agent: `POST agents/:id/deposit {ada}` (at least `minTopUpAda` from `GET prices`, 50 by default) answers 201 `{job}` with the steps `pay`, `deposit`, `credit`; the job then waits for the owner's transaction, built and signed as for an order: `POST agents/:id/deposit/build {utxos?}` answers `{unsignedTxCbor, outputs, total}`, one output of `ada` plus 5 tADA to the agent's own wallet; `POST agents/:id/deposit/pay {unsignedTxCbor, witnessSetHex}` (or `{signedTxCbor}`) submits it. The agent's wallet then deposits at Strike and the job waits for the credit (`creditedUsd` on the view); a job waiting for the owner's transaction says so under `waitingFor: ["pay"]`, and the page offers Pay now until the 45 minutes are up. The credit starts an agent that waited for a deposit. `GET agents/:id/deposits` lists them, `POST agents/:id/deposits/retry` runs the newest again from the failed step. One deposit at a time per agent. `npm run owner -- deposit <name> <ada>`, `deposits <name>`, `retry-deposit <name>`.

Unwind: `POST agents/:id/unwind` stops the agent (if it is not stopped already) and then lets it quote only the side that sells its Midnight inventory down, each fill hedged as usual, until what is left is under Strike's smallest order; a Strike position still worth an order is then closed and the agent is stopped for good. The card says `status: "unwinding"` meanwhile, `GET agents` carries `unwinding`. The answer is `{status: "unwinding", inventoryBtc, strikePositionBtc, inventoryUsd}`. A stop halts an unwind; a newly signed mandate ends it. The tUSD the inventory becomes stays in the agent's Midnight wallet. `npm run owner -- unwind <name>`.

Strike keys: `GET agents` carries `strikeKey: {accountId, publicKey, connectedAt} | null` per agent: the account builder connect made for it, null for a built-in that only ever had the shared key. `POST agents/:id/strike-key/rotate` makes a fresh API wallet for the agent's Strike account through builder connect (the same account; Strike revokes the old key) and swaps the running agent onto it: `{accountId, publicKey, connectedAt, sameAccount}`. `npm run owner -- rotate-strike-key <name>`.

For the page's "Connect an agent" section: a tools address may now need a key. The owner issues one under Keys (or orders the agent with one); from then on the agent's `/mcp/<agentId>` answers only with `Authorization: Bearer <key>` and 401 otherwise. Without a key the address stays open as before, so the connect flow as it stands keeps working; it should show the owner's key state (`GET agents` → `toolsKey`) and tell the outside mind to send the key. Tools keys: `POST agents/:id/key` issues a key for one of the session's agents (in the loop or still being set up), shown once as `{agentId, key, prefix, issuedAt}`; the key before it stops working. With `X402_PRICE_KEY` above 0 the call is paid by x402 (402 first). `DELETE agents/:id/key` revokes it. An agent with a key answers at `/mcp/<agentId>` only with `Authorization: Bearer <key>` (401 otherwise); without one its endpoint stays open as today. `GET agents` shows `toolsKey: {prefix, issuedAt} | null` per agent. `npm run owner -- key <name>` and `revoke-key <name>`; `npm run pay-demo` sends `AGENT_KEY` when set.

## The feed, with real samples

`meta` — `markets` is every market's mark, funding and last two hours of marks: `{ "BTC-USD": { mark, funding, marks: [{t, p}] }, "ADA-USD": …, "SOL-USD": … }`, one entry per round, kept in `data/marks.json` across restarts, so a chart is full on the first poll and the page's market switch has all three. `orders.marketsOff` lists the markets closed for new agents. `strikeMark` and `marks` repeat BTC-USD for older readers. `strikeLiquidity` names who stands on the other side of the hedges when the venue has no market maker (our own testnet liquidity account), null when it is the real book. `midnightBoard` is where quotes wait for their taker: `server` (the offer board) or `gateway` (this process hands the halves over; for a network without the board). `attestEveryMs` is how often a window attestation is made, for the page's countdown.

`agents` — one card per agent. `type` is `mm`, `citizen` or `rogue`; `mind` is `rules` or `claude`; `status` is `quoting`, `hedging` (a hedge is pending), `watching` (citizen), `probing` (the rogue, one refused attempt a round), `frozen` (a late hedge), `paused` (by its owner), `stopped` (by its owner until a new mandate is signed, or `stoppedReason: "deposit needed"` for an owner's agent whose Strike account holds nothing), `unwinding`, `starting` (not in the loop yet; an agent being set up from the page also carries `onboarding`, see the owner API). `mandate.full` is the whole mandate. `legs` has one entry per market the agent trades (its mark, inventory, Strike position, net delta, unhedged value, open quotes, pending and resting hedges, frozen); `midnight.btc` is the first market's base coin, `midnight.bases` every base coin by pair. `maxHedgeLatencySec` is the slowest hedge of a fill in this run, the same number the reconciler claims. The day's figures (`day` is the UTC date): `equityUsd` (Midnight holdings at the mark, plus `midnight.reservedUsd`, the coins locked in open quotes, plus Strike margin balance; unchanged in a round where a market has no mark), `equityStartUsd` (the day's first reading, moved by payouts and deposits) and `pnlPct`, `spreadCapturedUsd` (what fills earned against the mark), `hedgeCostUsd` (Strike fees, builder fees and slippage against the mark), `strikeVolumeUsd`, `builderFeesUsd`; `wallets` (Cardano address, Midnight "hidden").

`fills` — a Midnight fill (with the swap's txHash) and, as separate entries, the Strike fills of hedges. Once the hedger has closed a Midnight fill, the fill's entry carries `hedge`: `how` is `market` (a Strike market order), `limit` (a resting limit that filled), `netted` (a fill of the other side closed it, no Strike order) or `dust` (a few dollars left, not worth an order); `clientOrderIds` are the Strike orders involved (several when one order covered part and another the rest), `price` their size-weighted fill price, `latencySec` fill to hedge. Until then the entry has no `hedge`. The `strikeFill` entries are the raw Strike side; match them to a fill by `clientOrderIds`.

`refusals` — what the checks refused, with the rule broken, its pair and market.
```json
{ "refusals": [ { "ts": "…", "agentId": "rogue", "venue": "midnight", "rule": "midnight.maxSpreadBps", "limit": 100, "attempted": 450, "action": "quote", "pair": "tBTC/tUSD", "symbol": "BTC-USD" } ] }
```
Markets: a maker trades one or more markets, named in `strike.markets` with their pairs in `midnight.pairs` in the same order (`BTC-USD` with `tBTC/tUSD`, `ADA-USD` with `tADA/tUSD`, `SOL-USD` with `tSOL/tUSD`); an order whose pairs do not match its markets is refused, and a mandate change cannot change the markets. The limits (`maxNetDeltaUsd`, `maxPositionUsd`, `maxOpenQuotes`) hold on each market. The citizens take on every pair. Quotes and fills carry `pair`; sizes are in the market's base asset, the field is still named `sizeBtc`. An agent's card carries `legs`: per market its mark, inventory, Strike position, net delta, unhedged value, open quotes and pending hedges; `midnight.bases` holds every base asset the wallet has.

Rules you will see: `strike.maxPositionUsd`, `strike.priceBandPct`, `strike.markets`, `strike.maxLeverage`, `midnight.maxQuoteUsd`, `midnight.minSpreadBps`, `midnight.maxSpreadBps`, `midnight.maxOpenQuotes`, `midnight.quoteTtlSec`, `midnight.pairs`, `risk.maxNetDeltaUsd`, `risk.dailyLossStopPct`, `risk.maxActionsPerMin`, `size`, `mandate`, `signature`, `expiry`, `frozen`, `stopped`. The rogue's eight live attempts hit `midnight.maxSpreadBps`, `strike.maxPositionUsd`, `risk.maxNetDeltaUsd`, `midnight.maxOpenQuotes`, `strike.priceBandPct`, `midnight.maxQuoteUsd`, `strike.markets` and `strike.maxLeverage`; a maker's own hedge refusals stay in the decision log, not on `refusals`.

`proofs` — per maker, from the reconciler: the four badge claims as numbers, the violations (an array, each with its rule), counts, and whether the decision log's hash chain is intact. The reconciler runs on a timer every 5 × `roundMs` and at shutdown, over every market the agent trades (Strike's fills per market, the delta walk per market, the delta claim the largest market's); its orders are the hedges it placed, the resting limits, the owner's closes and the tool orders, all known by their ids.
```json
{ "proofs": [ { "agentId": "mm-rule", "reconciled": "2026-10-21T19:22:57.969Z",
  "claims": { "violations": 0, "maxNetDeltaUsd": 0, "maxFillToHedgeSec": 0, "venuesOutsideMandate": 0 },
  "violations": [], "counts": { "midnightFills": 0, "hedgesPlaced": 0, "hedgesFilled": 0, "strikeFills": 0, "refusals": 0 }, "logChain": "934 entries this run, chain intact" } ] }
```
Badges: `no-violations` (violations = 0), `delta-held` (maxNetDeltaUsd ≤ mandate), `hedged-in-time` (maxFillToHedgeSec ≤ hedgeWithinSec), `allowed-venues` (venuesOutsideMandate = 0).

The same card carries the on-chain attestations: the agent's attester id, the vault, the mandate anchor (an anchor from an earlier run keeps that run's `txHash`) and the last window. A window is attested on a timer every `ATTEST_EVERY_ROUNDS` × `roundMs` (10 rounds by default) and once at the end of a bounded run.
```json
{ "agentId": "mm-rule", "attesterId": "46ef2032…", "vault": "e7ffe63b…",
  "mandate": { "payloadHash": "8b0f8ce6…", "txHash": "009e42cc…", "status": "succeeded", "verified": true, "at": "2026-10-21T19:58:53.657Z" },
  "lastAttestation": { "at": "…", "window": { "from": "…", "to": "…" }, "payloadHash": "…", "txHash": "…", "status": "succeeded", "verified": true, "decisions": 12, "fills": 2 } }
```
`verified` is the answer of a live check against the contract; anyone with a NIGHTGATE MCP server can repeat it with the attester id and payload hash.

The badges on chain, under `badges` on the same card: the reconciler's four claims go into one document (its hash attested, its Merkle root anchored), and each badge is a zero-knowledge proof that one field is at most the mandate's limit. A false claim earns nothing and costs no transaction (`status: "false"`); the others are proven and verified against live state. Verifiers need the attester id, the payload hash, the field key and the threshold, nothing else; the numbers stay hidden. Written on a timer every `BADGES_EVERY_ROUNDS` × `roundMs` (30 rounds by default) and at shutdown, for makers with fills to prove.
